# AI 활용 설계

## 1. Agent 구조
- 패턴: 단일 Agent + Tool-use 루프 (최대 5회 반복으로 무한 루프 방지)
- 도구: search_recipes(RAG), save_memory(Memory 쓰기), add_to_shopping_list(DB 쓰기)
- 의사결정 근거: 도구가 3개로 적고 서로 순서 의존성이 낮아,
  멀티 에이전트보다 단일 에이전트가 지연, 비용, 디버깅 측면에서 유리하다고 판단.

## 2. RAG 파이프라인
- 색인: 레시피 텍스트(제목+재료+조리법) → Voyage 임베딩(512d) → pgvector(HNSW, cosine)
- 검색: 질의 임베딩 → 상위 k=4, 선택적으로 조리시간 필터(SQL where)
- 생성: 검색 결과를 tool_result로 전달, "검색 결과 밖 레시피 금지" 규칙으로 환각 억제
- 한계와 개선 후보: 재료 일치율 기반 재랭킹, 하이브리드(키워드+벡터) 검색

## 3. Long-term Memory
- 저장 대상: 알레르기, 비선호, 식단, 조리 수준, 기타 (5개 kind)
- 쓰기: Agent가 대화에서 감지 시 save_memory 호출 (중복 저장 방지)
- 읽기: 매 요청마다 시스템 프롬프트에 주입
- 투명성: '내 기억 보기' 화면과 '내 데이터 삭제' 제공
- 단기 기억: 최근 10개 메시지만 대화 컨텍스트로 사용 (토큰 비용 통제)

## 4. 멀티모달
- 입력: 냉장고 사진 → JSON(재료명, 양, 신뢰도)
- 환각 방지: "보이는 것만, 불확실하면 low" 지시 + 사용자 확인/수정 단계(Human-in-the-loop)

## 5. 프롬프트 엔지니어링 기법
| 기법 | 적용 |
|---|---|
| 역할 부여 | "한국어 요리 코치 FridgeMate" |
| 구조화 출력 | Vision 결과를 JSON 스키마로 강제 |
| 제약 규칙 | 알레르기 제외, 검색 결과 외 금지 |
| 컨텍스트 주입 | Memory, 확정 재료를 시스템 프롬프트에 삽입 |
| 도구 설명 | 도구별 description과 input_schema로 호출 시점 유도 |

## 6. 안전 및 윤리
- 모든 AI 응답에 "AI 생성 콘텐츠" 표시, 배너 상시 노출
- 알레르기 강제 제외 + 확인 안내 문구, 의료 조언 아님을 명시
- 이미지 비저장, 최소 수집, 동의 체크, 삭제 기능
- API 키는 서버 환경변수로만 관리 (.env는 .gitignore)

## 7. 평가 방법
- 오프라인: 알레르기 시나리오 20개를 만들어 금지 재료 포함 추천 0건 확인
- 온라인: 사용자 테스트(👍/👎 비율, 설문)
