# 프로젝트 기획서: FridgeMate

## 1. 문제 정의
- 1인 가구, 대학생, 직장인은 냉장고 재료를 제때 쓰지 못해 음식물 쓰레기가 생기고,
  "오늘 뭐 먹지?"를 매번 고민하며 불필요한 배달, 장보기 비용을 지출한다.
- 기존 레시피 앱은 (1) 재료를 일일이 직접 입력해야 하고 (2) 알레르기, 취향을 기억하지 못하며
  (3) "있는 재료 기준"이 아니라 "요리 기준" 검색이라 불편하다.

## 2. 타겟 사용자
| 페르소나 | 특징 | 핵심 니즈 |
|---|---|---|
| 자취 대학생 (20대) | 요리 초보, 예산 제한 | 간단한 레시피, 재료 낭비 방지 |
| 직장인 1인 가구 (30대) | 시간 부족 | 15분 내 요리, 장보기 자동화 |
| 식이 제한자 | 알레르기, 채식 등 | 안전한 필터링, 선호 기억 |

## 3. 해결 방식 (AI 활용)
| 기능 | AI 기법 | 이유 |
|---|---|---|
| 재료 인식 | 멀티모달(Vision) LLM | 수동 입력 제거, 가장 큰 UX 개선 |
| 레시피 추천 | RAG (pgvector) | 환각 방지, 검증된 레시피 DB 기반 |
| 개인화 | Long-term Memory | 매번 알레르기 재입력 방지 |
| 대화 흐름 제어 | Tool-use Agent | 검색, 저장, 목록 생성을 LLM이 판단해 수행 |
| 주간 알림 | n8n + LLM | 코드 없이 스케줄링, 개인화 문구 생성 |

## 4. 기술적 접근 및 선정 근거
| 영역 | 선택 | 근거 |
|---|---|---|
| LLM | Claude API | 이미지 입력과 tool-use를 한 API로 지원, 한국어 품질 |
| 임베딩 | Voyage AI | Anthropic 권장 임베딩, 한국어 지원 |
| 백엔드 | FastAPI | 비동기, 자동 문서화(/docs), Python 학습 역량 활용 |
| DB + Vector | Supabase (Postgres + pgvector) | 관계형 데이터와 벡터 검색을 한 곳에서 처리, 무료 티어 |
| 프론트 | HTML/CSS/JS (FastAPI가 정적 서빙) | 배포 단순화, 모바일에서 카메라 업로드 가능 |
| 자동화 | n8n | 노코드 스케줄, 알림 연동 (Python + 노코드 조합 요건 충족) |
| 배포 | Render (무료 티어) | GitHub 연동 자동 배포 |

## 5. 일정 계획 (4주, 조정 가능)
| 주차 | 목표 | 산출물 |
|---|---|---|
| 1주 | 문제 정의, 기획서, 명세서, 아키텍처, 레시피 데이터 수집 | docs/, ERD, 레시피 CSV |
| 2주 | RAG 파이프라인, Vision, Agent 백엔드 | 동작하는 API |
| 3주 | 프론트 연동, Memory, n8n, **배포(알파)** | 배포 URL, 내부 테스트 |
| 4주 | 사용자 테스트(5명+), 피드백 반영, 발표 준비 | 테스트 결과, 발표 자료 |

## 6. 성공 지표
- 테스터 5명 이상(목표 10명), 과제 완료율 80% 이상
- 만족도 평균 4.0/5.0 이상
- 알레르기 재료 포함 레시피 추천 **0건** (안전 지표)
- AI 응답 평균 8초 이내 (이미지 인식 제외)

## 7. 리스크와 대응
| 리스크 | 대응 |
|---|---|
| 재료 오인식 | 인식 결과를 사용자가 수정, 확인한 뒤 진행 (Human-in-the-loop) |
| 알레르기 안전 | 시스템 프롬프트 강제 규칙 + 사후 검증 + 면책 문구 |
| API 비용 | 사용자별 일일 호출 상한, 이미지 리사이즈 |
| 무료 서버 콜드스타트 | 발표/테스트 전 워밍업, 헬스체크 핑 |
